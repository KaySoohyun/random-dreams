# Fase 0 · Módulo 0.1 — Definición de Producto

> Proyecto: Random Dreams — generación IA de contenido personalizado
> Fuente de productos: `docs/productos.md`
> Estado: borrador v1.1 — sujeto a revisión con stakeholders

---

## 1. Alcance funcional

### MVP

- Catálogo de los **6 productos** con ficha de detalle y selección única (sin carrito).
- **Formulario dinámico** configurable por producto (`Product.formSchema`), validado con Zod en frontend y backend, sin persistencia temporal (si el usuario abandona antes de confirmar, pierde la respuesta).
- **Checkout de confirmación** unitario (sin pasarela de pago): `Order.paymentStatus` transiciona `pending → approved` de forma simulada.
- **Generación IA asíncrona**: pipeline Inngest (Gemini genera el texto del producto y compone el prompt; Hugging Face genera la imagen), con reintentos, timeouts y estados de progreso (`queued / processing / completed / error`).
- **Entrega del resultado**: página de resultado con visualización del texto + imagen y descarga directa.
- **Backend core**: gestión de órdenes, formularios y logs de generación (`GenerationLog`).

### V1

- Autenticación y cuenta de usuario (email + OAuth opcional, recuperación de contraseña, perfil).
- Almacenamiento en la nube (Supabase Storage, tier gratuito) con subida automática del resultado (texto + imagen) y nombrado por `usuario/orden`.
- Panel de usuario con historial de generaciones y redescarga de resultados previos.
- `Order.userId` pasa a ser obligatorio para usuarios autenticados.

### V2

- Optimización y escalabilidad: caché de prompts, concurrencia del pipeline, limpieza/expiración de archivos no reclamados.
- Seguridad y cumplimiento: hardening de auth, manejo de datos personales de formularios, retención de archivos (GDPR).
- Analítica de producto: instrumentación de eventos y dashboard de conversión.
- Extensibilidad de catálogo: nuevos productos sin cambios estructurales + panel admin de productos/formularios.

## 2. Los 6 productos

Cada producto se define por datos: `formSchema` (JSON) y plantillas de prompt de texto (`ai_text_template`) e imagen (`ai_prompt_template`). **No hay precios ni moneda definida** (sin pasarela de pago; el valor se define cuando exista un modelo de negocio).

> **Modelo de datos confirmado:** los productos generan **texto + imagen**. La plantilla se separa en `ai_text_template` (texto, vía Gemini) y `ai_prompt_template` (imagen, vía Hugging Face).

### 2.1 Souvenir de Vida Paralela

*"Fotografía e historia de tu vida en un universo paralelo donde elegiste otra carrera/país".* Recuerdos de cosas que nunca pasaron: una crónica personal y un retrato de esa realidad alternativa.

**Formulario (`formSchema`):**

```json
{
  "fields": [
    { "name": "nombre", "label": "Tu nombre", "type": "text", "required": true, "maxLength": 60, "placeholder": "Ej. Martín" },
    { "name": "vida_real", "label": "Tu vida real (carrera o país actual)", "type": "text", "required": true, "maxLength": 120, "placeholder": "Ej. soy contador viviendo en Buenos Aires" },
    { "name": "punto_quiebre", "label": "El punto de quiebre", "type": "text", "required": true, "maxLength": 160, "placeholder": "Ej. el día que rechacé la beca para estudiar música" },
    { "name": "camino_alternativo", "label": "Lo que elegiste en ese universo paralelo", "type": "text", "required": true, "maxLength": 160, "placeholder": "Ej. me fui a estudiar piano a Viena" },
    { "name": "anios_despues", "label": "Años después del punto de quiebre", "type": "number", "required": false, "min": 1, "max": 60, "placeholder": "Ej. 10" },
    { "name": "tono_relato", "label": "Tono del relato", "type": "select", "required": true, "options": ["Nostálgico", "Épico", "Humorístico", "Melancólico"] },
    { "name": "estilo_retrato", "label": "Estilo del retrato", "type": "select", "required": true, "options": ["Pintura al óleo", "Fotografía fotorrealista", "Ilustración editorial"] }
  ]
}
```

**Plantilla de texto (`ai_text_template`):**

```
Escribe una crónica personal de {nombre}, {anios_despues} años después del punto de quiebre: {punto_quiebre}, en un universo paralelo donde eligió {camino_alternativo} en lugar de {vida_real}. Relato en primera persona, tono {tono_relato}. Incluye detalles de su vida cotidiana, sus logros, sus dudas y una escena clave de ese universo. Formato de diario/crónica.
```

**Plantilla de imagen (`ai_prompt_template`):**

```
Genera un retrato de {nombre} viviendo su vida en el universo paralelo donde eligió {camino_alternativo}. Estilo: {estilo_retrato}. Escena: un momento cotidiano significativo que refleje {tono_relato}, {anios_despues} años después del punto de quiebre. Ambientación coherente con la vida descrita. Alto detalle, composición tipo retrato/documental.
```

### 2.2 Quimera de Biotopo

*"Adopta tu quimera":* criatura fantástica única, combinación de 2 o 3 animales, con su ficha de adopción completa.

**Formulario (`formSchema`):**

```json
{
  "fields": [
    { "name": "nombre_criatura", "label": "Nombre de tu quimera (opcional)", "type": "text", "required": false, "maxLength": 40, "placeholder": "Ej. Fénix del Pantano" },
    { "name": "animales", "label": "Combinación de animales (elegí 2 o 3)", "type": "multiselect", "required": true, "min": 2, "max": 3, "options": ["León", "Águila", "Serpiente", "Lobo", "Pulpo", "Cabra", "Pez", "Murciélago", "Tortuga", "Escorpión"] },
    { "name": "clima", "label": "Clima preferido", "type": "select", "required": true, "options": ["Tropical", "Desierto", "Tundra", "Selva", "Marino", "Montaña"] },
    { "name": "agresividad", "label": "Nivel de agresividad", "type": "select", "required": true, "options": ["Dócil", "Travieso", "Territorial", "Peligroso"] },
    { "name": "habitat", "label": "Hábitat de adopción", "type": "select", "required": false, "options": ["Departamento", "Casa con jardín", "Reserva natural", "Fantasía libre"] }
  ]
}
```

**Plantilla de texto (`ai_text_template`):**

```
Crea la ficha de adopción de la quimera {nombre_criatura}, resultado de la combinación de {animales}. Clima preferido: {clima}. Nivel de agresividad: {agresividad}. Incluye: descripción física, árbol genealógico, dieta absurda y manual de cuidados. Tono de catálogo científico de criaturas fantásticas con humor seco. Formato ficha técnica.
```

**Plantilla de imagen (`ai_prompt_template`):**

```
Render 3D estilo ilustración científica de la criatura fantástica {nombre_criatura}, combinación de {animales}, adaptada al clima {clima}, nivel de agresividad {agresividad}. Fondo de estudio de biología, anatomía detallada, luz neutra, etiqueta de espécimen en la esquina.
```

### 2.3 Manual de Contingencia Absurda

*"Plan de evacuación personalizado si tu vecindario es invadido por [X]".* Consultoría de emergencia hiperlocal y disparatada.

**Formulario (`formSchema`):**

```json
{
  "fields": [
    { "name": "ciudad", "label": "Ciudad o dirección", "type": "text", "required": true, "maxLength": 100, "placeholder": "Ej. Barrio de La Boca, Buenos Aires" },
    { "name": "amenaza", "label": "Tipo de amenaza", "type": "text", "required": true, "maxLength": 80, "placeholder": "Ej. patos gigantes, viajeros del tiempo desorientados, zombies victorianos" },
    { "name": "tono_manual", "label": "Tono del manual", "type": "select", "required": true, "options": ["Formal y técnico", "Humor absurdo", "Apocalíptico serio", "Parodia institucional"] },
    { "name": "nivel_detalle", "label": "Nivel de detalle", "type": "select", "required": false, "options": ["Rápido (1 página)", "Completo (2-3 páginas)", "Exhaustivo (protocolo completo)"] }
  ]
}
```

**Plantilla de texto (`ai_text_template`):**

```
Redacta un manual de evacuación personalizado para {ciudad} ante la invasión de {amenaza}. Incluye: instrucciones paso a paso, cláusulas de seguridad, rutas ficticias de evacuación y protocolos por situación. Tono: {tono_manual}. Nivel de detalle: {nivel_detalle}. Formato de manual institucional con pasos numerados y advertencias.
```

**Plantilla de imagen (`ai_prompt_template`):**

```
Genera un mapa esquemático de evacuación de {ciudad} ante la amenaza de {amenaza}. Estilo: plano técnico / cartel institucional, con rutas marcadas, puntos de encuentro, leyendas y advertencias. Tono: {tono_manual}. Esquemático, limpio, alta legibilidad.
```

  "fields": [

    { "name": "epoca", "label": "Época histórica", "type": "select", "required": true, "options": ["Antiguo Egipto", "Imperio Romano", "Reino Medio", "Renacimiento", "Siglo XVIII", "Era Victoriana", "Guerra Fría", "Retrofuturismo"] },

## 3. User flow end-to-end

```
┌──────────┐   ┌─────────────────┐   ┌──────────────────┐   ┌─────────────────────┐   ┌──────────────┐
│ Selección│ → │    Formulario    │ → │   Confirmación   │ → │   Generación IA     │ → │   Resultado   │
│ producto │   │  dinámico (Zod)  │   │ (sin pasarela)   │   │  asíncrona (Inngest)│   │ texto+imagen │
└──────────┘   └─────────────────┘   └──────────────────┘   └─────────────────────┘   └──────────────┘
```

### Paso 1 — Selección
- El usuario entra a `/catalogo`, ve los 6 productos (datos de `Product`) y elige uno (`/producto/[slug]`).
- Decisión: selección única. No hay carrito.

### Paso 2 — Formulario
- El formulario se renderiza desde `Product.formSchema`.
- Validación con **Zod** en el cliente (feedback inmediato) y en el servidor (Server Action).
- Al enviar, se crea `Order` (estado `pending`) y `FormSubmission` con `form_data` en la **misma transacción**.
- **Sin persistencia temporal**: si el usuario abandona antes de confirmar, pierde la respuesta del formulario.

### Paso 3 — Confirmación (pago simulado)
- El usuario revisa un resumen (producto, respuesta del formulario) en `/checkout/[orderId]`.
- Confirma; `paymentStatus` transiciona `pending → approved` (simulado; sin pasarela).
- Al confirmar, se dispara el evento `order/confirmed` en Inngest.
- Estados de transacción modelados: `pending` / `approved` / `rejected` (preparado para integración futura).

### Paso 4 — Generación
- El usuario es dirigido a `/generacion/[orderId]` y hace **polling** del estado.
- Pipeline Inngest:
  - Paso 1 · `generateText` (Gemini): genera el texto del producto (crónica, ficha, manual, biografía o receta) **y** compone el prompt de imagen a partir de `form_data` + plantillas.
  <!-- Es posible generar la imagen usando el promt que devuelve gemini, hay que revisar la fidelidad de la platilla vs el promnt de gemini -->
  - Paso 2 · `generateImage` (Hugging Face): genera la imagen del producto.
  - Paso 3 · `uploadResult`: persiste texto + imagen (V1 en Supabase Storage).
  - Paso 4 · `markCompleted`: actualiza `GeneratedResult` y escribe en `GenerationLog`.
- Estados: `queued → processing → completed | error`.
- **Errores**: reintentos con backoff automáticos; si persisten, estado `error`, log en `GenerationLog` y el usuario puede **reintentar con un botón manual**.
- Formato de salida: texto **`.txt`** + imagen **`.png`** (1024×1024), resuelto en el módulo 0.2.

### Paso 5 — Entrega
- `/resultado/[orderId]` muestra el texto y la imagen generados con botón de **descarga directa**.
- MVP: archivos servidos desde el pipeline (sin persistencia de larga duración).
- V1: se suben a Supabase Storage, se registran en `StorageAsset` y quedan disponibles en el historial del usuario.

### Diagrama de estados de generación

```
         ┌────┐
         │queued│
         └──┬──┘
            ▼
      ┌──────────┐   éxito   ┌───────────┐
      │processing├──────────►│ completed │
      └────┬─────┘           └───────────┘
           │ fallo (reintentos agotados)
           ▼
       ┌──────┐
       │ error│  → reintentable por el usuario
       └──────┘
```

## 4. Decisiones del módulo (resueltas)

| Decisión | Resolución |
|---|---|
| Catálogo | **6 productos** (los definidos en `docs/productos.md`); `requerimientos.md` se actualiza a 6 |
| Precios y moneda | **Sin precios ni moneda** (no hay pasarela de pago) |
| Modelo de datos de plantillas | **Separar** `ai_text_template` + `ai_prompt_template` en `Product` |
| Campos de formulario | **Confirmados tal cual** en la sección 2 |
| Persistencia temporal | **Sin persistencia**: si el usuario abandona antes de confirmar, pierde la respuesta |
| Reintento ante error | **Botón manual** de reintento tras agotarse los reintentos automáticos |

**Resuelto en 0.2:** el formato del resultado es texto **`.txt`** + imagen **`.png`** (modelos: Gemini flash + FLUX.1-schnell). Ver `docs/0.2-arquitectura-tecnica.md` y `docs/contrato-ia.md`.
