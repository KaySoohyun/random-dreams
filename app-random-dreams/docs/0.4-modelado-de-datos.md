# Fase 0 · Módulo 0.4 — Modelado de Datos

> Proyecto: Random Dreams
> Base: `docs/0.1-definicion-producto.md`, `docs/0.2-arquitectura-tecnica.md`
> Estado: borrador v1.0 — sujeto a revisión (spec-first: sin archivos de código aún)

---

## 1. Objetivo

Definir el modelo relacional (entidades, relaciones, enums, índices), el borrador de `schema.prisma`, las reglas de consistencia del flujo de generación y el seed de los 6 productos.

## 2. Diagrama entidad-relación

```
 Product 1 ──── N Order 1 ──── 1 FormSubmission
   │  │          │   │  │  │
   │  │          │   │  │  └── 1 GeneratedResult
   │  │          │   │  │
   │  │          │   │  └───── N GenerationLog
   │  │          │   │
   │  │          │   └──────── N StorageAsset        (V1)
   │  │          │
   │  │          └─ N ── User (nullable en MVP; obligatorio en V1)
   │  └────────── N GeneratedResult  (denormalizado: consultas por producto)
   └────────────── N Order
```

Cardinalidades clave:
- `Product 1─N Order` · `User 1─N Order` (nullable en MVP) · `Order 1─1 FormSubmission`
- `Order 1─1 GeneratedResult` · `Order 1─N GenerationLog` · `Order 1─N StorageAsset` (V1)

## 3. Entidades

### 3.1 `User` (V1 — Auth.js)

| Campo | Tipo | Reglas |
|---|---|---|
| `id` | `String` cuid | PK |
| `email` | `String` | `@unique` |
| `emailVerified` | `DateTime?` | — |
| `name` / `image` | `String?` | perfil |
| `createdAt` / `updatedAt` | `DateTime` | — |

> En MVP los pedidos se crean **sin usuario** (`Order.userId` null).

### 3.2 `Product`

| Campo | Tipo | Reglas |
|---|---|---|
| `id` | `String` cuid | PK |
| `slug` | `String` | `@unique`; usado en `/producto/[slug]` |
| `name` | `String` | — |
| `tagline` | `String` | descripción de 1 línea (catálogo) |
| `description` | `String` | ficha de detalle |
| `formSchema` | `Json` | formulario dinámico (Zod), fuente única |
| `aiTextTemplate` | `String` | plantilla de texto (Gemini) |
| `aiPromptTemplate` | `String` | plantilla de imagen (HF) |
| `imageUrl` | `String?` | ilustración del catálogo (placeholder en MVP) |
| `active` | `Boolean` | `@default(true)`; ocultar sin borrar |
| `sortOrder` | `Int` | orden del catálogo |

### 3.3 `Order`

| Campo | Tipo | Reglas |
|---|---|---|
| `id` | `String` cuid | PK; se expone como `orderId` en URLs |
| `productId` | `String` | FK → `Product` |
| `userId` | `String?` | FK → `User` (null en MVP) |
| `paymentStatus` | `PaymentStatus` | `PENDING → APPROVED`; `REJECTED` reservado |
| `confirmedAt` | `DateTime?` | set al aprobar |
| `createdAt` / `updatedAt` | `DateTime` | — |

Índices: `userId`, `paymentStatus`, `createdAt`.

### 3.4 `FormSubmission`

| Campo | Tipo | Reglas |
|---|---|---|
| `id` | `String` cuid | PK |
| `orderId` | `String` | `@unique` FK → `Order` (1:1) |
| `formData` | `Json` | respuesta validada con Zod **antes** de insertar |

### 3.5 `GeneratedResult`

| Campo | Tipo | Reglas |
|---|---|---|
| `id` | `String` cuid | PK |
| `orderId` | `String` | `@unique` FK → `Order` (1:1) |
| `productId` | `String` | FK → `Product` (denormalizado, consultas admin) |
| `aiRequestPayload` | `Json` | snapshot del input del pipeline (trazabilidad/reproducibilidad) |
| `aiResponseStatus` | `AiResponseStatus` | `QUEUED → PROCESSING → COMPLETED \| ERROR` |
| `textFileName` / `textContent` | `String?` | MVP: texto `.txt` guardado en DB |
| `textFileUrl` | `String?` | V1: URL de Supabase Storage |
| `imageFileName` / `imageBytes` | `String?` / `Bytes?` | MVP: PNG guardado en DB (V1: `imageFileUrl`) |
| `imageFileUrl` | `String?` | V1 |
| `error` | `String?` | último error (para el botón de reintento) |
| `retryCount` | `Int` | `@default(0)`; reintentos manuales |
| `startedAt` / `completedAt` | `DateTime?` | latencia |
| `createdAt` / `updatedAt` | `DateTime` | — |

Índices: `aiResponseStatus`, `productId`.

> **MVP vs V1:** en MVP el contenido se persiste en Postgres (`textContent`, `imageBytes`) para servir el resultado y permitir redescarga, sin garantía de retención. En V1 se sube a Supabase Storage y `GeneratedResult` solo guarda URLs; `StorageAsset` registra los archivos.

### 3.6 `GenerationLog`

| Campo | Tipo | Reglas |
|---|---|---|
| `id` | `String` cuid | PK |
| `orderId` | `String` | FK → `Order` |
| `step` | `PipelineStep` | `GENERATE_TEXT / GENERATE_IMAGE / UPLOAD_RESULT / MARK_COMPLETED` |
| `status` | `PipelineStepStatus` | `RUNNING / SUCCESS / FAILED` |
| `payload` | `Json?` | datos del paso (prompt de imagen, tamaños…) |
| `error` | `String?` | detalle del fallo |
| `durationMs` | `Int?` | latencia por paso (útil para el spike 0.2) |
| `createdAt` | `DateTime` | — |

Índices: `(orderId, createdAt)`, `step`.
**Inmutable / append-only**: un reintento agrega filas nuevas, nunca actualiza las anteriores.

### 3.7 `StorageAsset` (V1)

| Campo | Tipo | Reglas |
|---|---|---|
| `id` | `String` cuid | PK |
| `orderId` | `String` | FK → `Order` |
| `kind` | `FileKind` | `TEXT \| IMAGE` |
| `storageKey` | `String` | `usuario_id/orden_id/resultado.{txt,png}` |
| `url` | `String?` | URL firmada temporal |
| `mimeType` | `String` | — |
| `sizeBytes` | `Int` | — |
| `expiresAt` | `DateTime?` | retención / limpieza (V2) |

Índices: `orderId`, `expiresAt`.

## 5. Borrador de `prisma/schema.prisma`

Se crea en el bootstrap del MVP, tras OK del usuario. Esquema (PostgreSQL + Prisma):

```prisma
generator client { provider = "prisma-client-js" }
datasource db { provider = "postgresql" url = env("DATABASE_URL") }

enum PaymentStatus { PENDING APPROVED REJECTED }
enum AiResponseStatus { QUEUED PROCESSING COMPLETED ERROR }
enum PipelineStep { GENERATE_TEXT GENERATE_IMAGE UPLOAD_RESULT MARK_COMPLETED }
enum PipelineStepStatus { RUNNING SUCCESS FAILED }
enum FileKind { TEXT IMAGE }

model User {
  id            String    @id @default(cuid())
  email         String    @unique
  emailVerified DateTime?
  name          String?
  image         String?
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt
  orders        Order[]
}

model Product {
  id              String   @id @default(cuid())
  slug            String   @unique
  name            String
  tagline         String
  description     String
  formSchema      Json
  aiTextTemplate  String
  aiPromptTemplate String
  imageUrl        String?
  active          Boolean  @default(true)
  sortOrder       Int      @default(0)
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
  orders          Order[]
  generatedResults GeneratedResult[]
}

model Order {
  id            String        @id @default(cuid())
  productId     String
  userId        String?
  paymentStatus PaymentStatus @default(PENDING)
  confirmedAt   DateTime?
  createdAt     DateTime      @default(now())
  updatedAt     DateTime      @updatedAt
  product       Product          @relation(fields: [productId], references: [id])
  user          User?            @relation(fields: [userId], references: [id])
  formSubmission FormSubmission?
  generatedResult GeneratedResult?
  generationLogs  GenerationLog[]
  storageAssets   StorageAsset[]
  @@index([userId])
  @@index([paymentStatus])
  @@index([createdAt])
}

model FormSubmission {
  id        String   @id @default(cuid())
  orderId   String   @unique
  formData  Json
  createdAt DateTime @default(now())
  order     Order    @relation(fields: [orderId], references: [id])
}

model GeneratedResult {
  id               String          @id @default(cuid())
  orderId          String          @unique
  productId        String
  aiRequestPayload Json
  aiResponseStatus AiResponseStatus @default(QUEUED)
  textFileName     String?
  textContent      String?
  textFileUrl      String?
  imageFileName    String?
  imageBytes       Bytes?
  imageFileUrl     String?
  error            String?
  retryCount       Int             @default(0)
  startedAt        DateTime?
  completedAt      DateTime?
  createdAt        DateTime        @default(now())
  updatedAt        DateTime        @updatedAt
  order            Order           @relation(fields: [orderId], references: [id])
  product          Product         @relation(fields: [productId], references: [id])
  @@index([aiResponseStatus])
  @@index([productId])
}

model GenerationLog {
  id         String            @id @default(cuid())
  orderId    String
  step       PipelineStep
  status     PipelineStepStatus
  payload    Json?
  error      String?
  durationMs Int?
  createdAt  DateTime          @default(now())
  order      Order             @relation(fields: [orderId], references: [id])
  @@index([orderId, createdAt])
  @@index([step])
}

model StorageAsset {
  id        String   @id @default(cuid())
  orderId   String
  kind      FileKind
  storageKey String
  url       String?
  mimeType  String
  sizeBytes Int
  expiresAt DateTime?
  createdAt DateTime @default(now())
  order     Order    @relation(fields: [orderId], references: [id])
  @@index([orderId])
  @@index([expiresAt])
}
```

## 6. Reglas de consistencia

| Escenario | Regla |
|---|---|
| Crear pedido | `Order` + `FormSubmission` se insertan en **la misma transacción** (Server Action). `paymentStatus = PENDING`. |
| Confirmar | `PENDING → APPROVED` (solo hacia adelante, validado en el servidor); se setea `confirmedAt`, se crea `GeneratedResult` (`QUEUED`) y se dispara `order/confirmed` en Inngest. |
| Pipeline | `QUEUED → PROCESSING` (inicio) → `COMPLETED \| ERROR`. Cada paso escribe un `GenerationLog` (inmutable). |
| Reintento manual | `ERROR → QUEUED` (re-trigger); `retryCount++`; se agregan logs nuevos, no se borran los anteriores. |
| Datos de entrada | `formData` y `aiRequestPayload` solo contienen JSON **validado con Zod**; nunca raw. |
| Borrado | No se eliminan órdenes; ocultar con `Product.active = false`. Retención según política (V2/GDPR). |

## 7. Índices y consultas calientes

| Consulta | Índice |
|---|---|
| Catálogo (`/catalogo`) | `Product.active` + `sortOrder` |
| Detalle (`/producto/[slug]`) | `Product.slug` (`@unique`) |
| Checkout / generación / resultado (`[orderId]`) | `Order.id` (PK) |
| Historial del usuario (V1) | `Order.userId` + `createdAt` |
| Admin: órdenes por estado | `Order.paymentStatus` |
| Polling de estado | `GeneratedResult.orderId` (`@unique`) |

## 8. Seed (`prisma/seed.ts`)

- Inserta los **6 productos** de `docs/0.1-definicion-producto.md` (slug, nombre, tagline, descripción, `formSchema`, `aiTextTemplate`, `aiPromptTemplate`) con `upsert` por `slug` (idempotente).
- Los `formSchema` se copian literalmente de la sección 2 del módulo 0.1.

## 9. Cumplimiento de requerimientos

| Requerimiento (MVP) | Cómo lo cubre el modelo |
|---|---|
| 6 productos data-driven | `Product.formSchema` + plantillas |
| Formulario dinámico validado | `Product.formSchema` (frontend/backend con Zod); `FormSubmission.formData` |
| Checkout sin pasarela | `Order.paymentStatus` `PENDING→APPROVED` |
| Generación asíncrona | `GeneratedResult.aiResponseStatus` + `GenerationLog` (trazabilidad) |
| Reintento ante error | `retryCount` + logs append-only |
| Resultado descargable | MVP: `textContent`/`imageBytes`; V1: `StorageAsset` + URLs |

## 10. Decisiones y abiertos

**Resueltas:**
1. Sin precios en `Order` (sin pasarela).
2. Contenido del resultado en Postgres durante MVP; URLs + `StorageAsset` en V1.
3. `GenerationLog` append-only con `durationMs` por paso.
4. `orderId` = `Order.id` (cuid) usado en URLs.

**Abiertos para el spike/MVP:**
- Tamaño real de `imageBytes` (FLUX 1024²) y costo de persistirlo en Postgres del tier gratuito (si excede, adelantar V1 storage).
- Formato exacto de `aiRequestPayload` (plantillas interpoladas completas vs referencias).
