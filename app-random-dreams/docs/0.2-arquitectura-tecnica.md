## 2. Diagrama de arquitectura

```
                        ┌─────────────────────────────────────┐
                        │        Navegador (cliente)           │
                        │  Server Components (SSR/ISR) + fetch │
                        └──────────────────┬──────────────────┘
                                           │  Server Actions (mutaciones)
                                           │  Polling (estado de generación)
                        ┌──────────────────▼──────────────────┐
                        │          Next.js (Vercel)            │
                        │  app/(store) · (auth) · cuenta · admin│
                        │  features/ · components/ · lib/services│
                        │  app/api/inngest (webhook)           │
                        └───────┬──────────────────┬──────────┘
                                │                  │
                    ┌───────────▼─────┐   ┌────────▼───────────┐
                    │  PostgreSQL     │   │  Inngest Cloud     │
                    │  (Prisma ORM)   │   │  (background fns)  │
                    │  Supabase/Neon  │   └────────┬───────────┘
                    └─────────────────┘            │ evento: order/confirmed
                                                   ▼
        ┌────────────────────────────────────────────────────────────────┐
        │          Pipeline de generación (función Inngest)               │
        │                                                                    │
        │   1. generateText   ──────────────►  Google Gemini (flash)         │
        │      (genera texto del producto +                                │
        │       compone el prompt de imagen)                                │
        │   2. generateImage  ──────────────►  Hugging Face FLUX.1-schnell   │
        │   3. uploadResult   ──────────────►  Supabase Storage (V1)         │
        │   4. markCompleted  ──────────────►  PostgreSQL + GenerationLog    │
        └────────────────────────────────────────────────────────────────┘
```

### Flujo

1. **Storefront** (Server Components, SSG/ISR) renderiza Home, catálogo y ficha de producto; SSR para formulario, checkout, generación y resultado.
2. El usuario completa el **formulario dinámico** (`Product.formSchema`); una Server Action valida con Zod, crea `Order` (`pending`) y `FormSubmission` en una transacción.
3. En **checkout** el usuario confirma; `paymentStatus` → `approved` (simulado, sin pasarela) y se dispara el evento `order/confirmed` en Inngest.
4. **Inngest** ejecuta el pipeline asíncrono; el frontend hace **polling** de `GeneratedResult.aiResponseStatus` (`queued → processing → completed | error`).
5. El resultado (texto `.txt` + imagen `.png`) se muestra en `/resultado/[orderId]` con descarga directa. En V1 se sube a **Supabase Storage** y queda en el historial.

## 4. Contrato de API de IA

Documento versionado: **`docs/contrato-ia.md`**.

Resumen:

- **Input del pipeline:** `{ productId, form_data, ai_text_template, ai_prompt_template }`
- **Texto (Gemini flash):** a partir de `ai_text_template` + `form_data` produce el texto del producto y el prompt de imagen final. Archivo de salida: **`.txt`** (UTF-8).
- **Imagen (FLUX.1-schnell):** a partir del prompt de imagen produce **`.png`** (1024×1024).
- **Output del pipeline:** `{ text_file, image_file, format: { text: 'txt', image: 'png' } }`

> **Pendiente de validar (spike):** la imagen puede generarse usando (a) el prompt de imagen compuesto por Gemini o (b) la `ai_prompt_template` interpolada directamente. Se evalúa la fidelidad de ambas opciones con una muestra de cada producto.

## 5. Almacenamiento cloud (tier gratuito)

- **Proveedor:** **Supabase Storage** (tier gratuito).
- **Uso:** persiste el resultado (`.txt` + `.png`) por `usuario/orden` (V1); en MVP el archivo se sirve desde el pipeline sin persistencia de larga duración.
- **Acceso:** bucket privado en producción; descargas con **URLs firmadas y con expiración**.
- **Retención:** `StorageAsset.expiresAt` según política (V2); limpieza programada de archivos no reclamados.
- **Nombrado:** `usuario_id/orden_id/resultado.txt` y `usuario_id/orden_id/resultado.png`.
- **Límites del tier gratuito:** a validar en el spike (cuota de GB, ancho de banda); si se superan, migrar a S3-compatible sin tocar el dominio (interfaz `StorageProvider`).

## 6. Decisiones resueltas en este módulo

| Decisión | Resolución |
|---|---|
| Formato de salida (diferida de 0.1) | Texto **`.txt`** + imagen **`.png`** |
| Modelo de imagen (Hugging Face) | **FLUX.1-schnell** (validar en spike) |
| Modelo de texto (Gemini) | **gemini-flash** (variante exacta a fijar en spike) |
| Proveedor de storage | **Supabase Storage** (tier gratuito) |
| Proveedor de IA | **Gemini** (texto) + **Hugging Face** (imagen) |
| Pasarela de pago | **Ninguna** (confirmación simulada) |

## 7. Riesgos y decisiones abiertas del módulo

| Tema | Detalle | Responsable |
|---|---|---|
| Rate limits del tier gratuito HF/Gemini/Supabase | Fallos por cuota durante generación o subidas | Spike 0.2 |
| Fidelidad del prompt de imagen (plantilla vs Gemini) | Calidad del resultado según cómo se componga el prompt | Spike 0.2 |
| Costo de Gemini flash y HF por generación | Costo operativo por pedido | Spike 0.2 |
| Variante exacta de gemini-flash y resolución final de imagen | `gemini-2.x-flash` según disponibilidad | Spike 0.2 |
| Timeout máximo de generación | Definir (ej. 90–120 s) y manejo de reintentos | Spike 0.2 |
| Escalamiento de storage en tier gratuito | Límites de GB y banda | V1 |
